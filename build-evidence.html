Architecture 01

Governed agent runtime

A planner may propose work; only deterministic policy can authorize tool execution.

Execution path
Request envelopetenant · actor · purpose→Plannersteps · cost · tools→Policy gateconsent · risk · budget→Tool registryversion · owner · scope→Resultbounded output
Human decisionApproval for sensitive, material or irreversible actions
Runtime safetyKill switch · timeout · retry policy · rollback contract
Evidence ledgerPlan · decision · tool call · output · exception · owner
Key decisions

Separate proposal from authorization. Declare identity, purpose and budget in the request envelope. Permit only registered tools.

Control boundaries

Consent and risk are evaluated before execution. Human approval is explicit, scoped and recorded—not inferred from chat context.

Failure modes

Unknown tool → deny. Missing consent → deny. Budget overrun → deny. Irreversible action → escalate. Timeout → contain and preserve evidence.

Reference stack

FastAPI boundary · planner/executor · policy service · tool registry · signed event ledger · Kafka/RabbitMQ adapters.

Architecture 02

Permission-aware RAG

Authorization determines the candidate corpus before relevance determines rank.

Query path
User contexttenant · role · purpose→ACL filterpermitted corpus→Hybrid retrieveBM25 · vector→RRF + rerankintent fit→Grounding gatecite · clarify · refuse
Document pathOCR/chunk → metadata → ACL inheritance → versioned index
Evaluation pathRecall · relevance · leakage · abstention · latency · cost
Evidence pathQuery → candidates → ranks → source spans → response policy
Key decisions

Filter before ranking. Preserve independent lexical and semantic signals. Attach citations through generation. Make abstention a successful outcome.

Control boundaries

Tenant and object ACLs constrain retrieval. Confidence policy selects answer, clarify or refuse. PII and purpose checks apply at query and output.

Failure modes

ACL leakage → refuse and alert. Sparse evidence → clarify. Low score or disagreement → refuse. Stale index → expose version and route repair.

Reference stack

Llama 3/self-hosted inference · Milvus/ChromaDB · BM25/RRF · reranker · FastAPI · citation and refusal policy.

Architecture 03

Delivery control tower

Deterministic services own facts; agents interpret variance; people own decisions.

Decision path
Source adaptersdelivery · finance · HR→Semantic contractsmetric · owner · lineage→Metric servicesdeterministic→Analyst agentvariance · confidence→Operating reviewaction · owner · date
Output adaptersExecutive narrative · PowerPoint · Excel · API · alert
Action registerDecision → commitment → due date → recovery signal → closure
Evidence lineageSource → transform → version → period → threshold → approved narrative
Key decisions

Keep arithmetic outside the model. Bind every KPI to lineage and ownership. Organize the review around material variance and action.

Control boundaries

Typed services constrain available metrics. Freshness and threshold policy control automated conclusions. Owners approve final narrative and actions.

Failure modes

Missing metric → block score. Stale evidence → exclude. Weak driver confidence → flag. Narrative without lineage → reject. Unowned action → cannot publish.

Reference stack

ClickHouse/PostgreSQL · typed semantic catalog · FastAPI metric services · planner/analyst agents · PowerPoint/Excel adapters.
